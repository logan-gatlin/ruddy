# Inferred structural type representations, Any, and JavaScript conversion

Status: ready-for-agent

## Problem Statement

Ruddy programs need to pass values through JavaScript when the original Ruddy type is unavailable at the eventual return site. They also need to accept arbitrary values created by JavaScript without pretending that those values already have a particular Ruddy type.

Generic extern declarations pose a related problem. A foreign identity function declared with the same type parameter in its argument and result should accept a Ruddy immutable array, receive an ordinary native array in JavaScript, and return a correctly reconstructed Ruddy immutable array. The adapter cannot make that conversion today when the parameter's representation is unknown. The current compiler rejects representation-polymorphic extern positions; its existing adapters primarily handle callable conventions and pass ordinary value positions through.

Attaching type descriptors to every value would impose runtime type information throughout the language. Specializing every generic function would introduce a different compilation model. Adding traits, nominal type identities, instance search, or user-written representation constraints would conflict with the intended structural language and complicate termination of type checking.

The required solution preserves structural equality, ordinary untagged Ruddy values, separate compilation, and terminating type checking. It obtains runtime type information only where boxing or foreign conversion actually needs it, without a new keyword or source syntax for requirements.

## Solution

Introduce compiler-generated runtime representations of Ruddy's structural types. Infer which representations each callable needs and pass them as hidden arguments using the existing evidence-passing infrastructure. Requirements remain explicit in compiler interfaces and bundle artifacts, but never need to be written in source.

Add the builtin value type `Any` and ordinary callable operations exposed through the standard `any` module. Upcasting packages a value with the runtime representation of its static source type. Downcasting obtains its target type through ordinary inference and returns an `Option` according to exact structural type equality. Only `Any` packages attach Ruddy type identity to otherwise ordinary payloads; descriptors may also travel as hidden arguments and captures where an operation needs them.

Use those same structural representations to drive native JavaScript conversion at ordinary extern and host-export interfaces. A generic foreign identity function uses one compiled adapter and receives a representation from each Ruddy caller. Array conversion recursively converts elements, copies into native JS array storage on export, and constructs persistent Ruddy storage on import.

Provide an opaque `ForeignValue` for values from the active backend's foreign environment and an explicit checked decoding operation in the standard `ffi` module. Each backend defines its supported foreign representations and conversions; the shared API does not promise cross-backend transport or identical capabilities. On the JavaScript backend, `ForeignValue` can carry any JavaScript value. Unknown foreign data is decoded against a requested Ruddy type; it is not assigned an invented original Ruddy identity. An `Any` sent through JavaScript as an opaque value instead keeps its original descriptor and payload when the same package comes back.

Portable library interfaces may retain inferred requirements. JavaScript-visible callable interfaces must satisfy every requirement from a concrete exported type or captured evidence. Unresolved requirements are rejected with guidance to export a concrete instantiation, including a `ForeignValue` instantiation when the signature permits it. There is no automatic default type or value-based guessing at the bundle boundary.

## Implementation Decisions

- Source grammar remains unchanged. `Any` and `ForeignValue` are compiler-known type constructors named using existing type syntax. Standard modules expose boxing, checked downcasting, and checked JS decoding through ordinary function names and calls. No `requires` keyword, constraint annotation, trait declaration, instance declaration, explicit type application, or general existential syntax is introduced.
- The standard `any` module exposes `upcast` from a generic value to `Any` and `downcast` from `Any` to the standard `Option` of an inferred target type. The standard `ffi` module exposes `decode` from `ForeignValue` to the standard `Result` of the inferred target type and a structural `DecodeError`. The result annotation or surrounding use determines a downcast or decode target.
- Runtime type representations are compiler-owned evidence. Source programs cannot fabricate a descriptor or substitute a user handler for its identity. There are no independently selectable `Typeable` and `JsAbi` implementations; conversion is a fixed structural operation over representations and the reviewed foreign protocol.
- A source annotation constrains ordinary types and effects while leaving representation needs to inference. Absence of written requirements does not assert erasure. Bodyless foreign declarations obtain their requirements from the reviewed conversion contract rather than by inspecting JavaScript source.
- Semantic callable interfaces carry latent representation demands at each arrow, with quantified demand information where higher-order composition needs it. Extend semantic types, schemes, substitution, generalization, instantiation, checking of annotations, compatibility, accepted semantic publication, and artifact interfaces consistently. Do not bolt demands onto only top-level definitions or infer them by rescanning callee bodies during linking.
- Representation demand variables and demand sets are separate from effect labels. Two independent type parameters may both be needed in one callable. Substitution can identify demands, but ordinary effect-constructor coalescing must not unify otherwise independent types. Canonical evidence layouts and adapters must remain valid when instantiation makes formerly distinct demands equal.
- Demand inference propagates through application, aliases, higher-order parameters, aggregates, control-flow joins, curried arrows, captures, recursive groups, and imported schemes. Calling an erased function does not intrinsically require a representation. Calling a function that forwards evidence can require it even when that caller performs no direct reflection.
- Known structural constructors produce descriptor constants or templates; unresolved type and row information is supplied through the corresponding inferred evidence. Do not derive element types from values, default unresolved cast targets, or manufacture details that an abstract package has hidden.
- Higher-order requirement polymorphism is inferred without source row syntax. Callable adapters reconcile the offered and required hidden argument layouts, including positions shared by functions with different demands. An available descriptor may be captured; a descriptor still required from a future caller must remain a latent requirement of that callable.
- Representation synthesis and requirement inference must have a documented termination discipline before they are considered complete: use finite semantic graphs and a finite symbolic demand analysis over admitted types and callable interfaces, memoize recursive dependencies, and avoid recursive specialization or repeated eager unfolding. Keep the existing language's restrictions on recursive types and polymorphic recursion. No user code or open implementation search runs in the type checker.
- Descriptor equality implements Ruddy structural equality rather than declaration identity, allocation identity, compiler-local symbols, or unchecked hash equality. Alias renaming, field declaration ordering, and bundle location cannot change identity where the semantic types are equal. Include primitive distinctions, array elements, record and sum structure, and the relevant callable contracts. Recursive equality uses graph-aware comparison or an equivalently sound canonical representation.
- Open rows, conditional presences, and existing producer-owned packages require evidence consistent with their inferred ownership and abstraction. Fully supplied concrete instances must work. If a representation cannot soundly be obtained at a particular abstract position, issue a focused diagnostic rather than guessing or exposing hidden identities.
- `Any` is a dedicated builtin package with existential semantics implemented by compiler rules. Boxing records the static source type at that point; checked downcasting uses exact structural equality, not numeric conversion, width subtyping, JS shape inspection, or arbitrary compatibility. A successful downcast exposes the stored Ruddy payload without ABI conversion. General existential introduction, elimination, and equality proofs are not source features.
- Ordinary payload representations stay unchanged outside the conversions this feature defines. Only `Any` packages attach Ruddy runtime type identity to stored payloads. Shared descriptors, hidden arguments, and closure captures are permitted; existing sum case tags and host runtime representation machinery are not a new promise of universal Ruddy reflection.
- `ForeignValue` holds arbitrary host values opaquely and preserves their host identity when simply retained or forwarded. It does not inspect a host value to assign a more specific Ruddy type. Boxing it into `Any` records `ForeignValue`; recovering a native value as another Ruddy type requires decoding.
- Opaque `Any` transport through JS preserves the package and its descriptor. Foreign import as `Any` accepts authentic packages, not lookalike objects. Runtime authenticity protects the package invariant and does not introduce nominal user-defined type equality. Native conversion of an ordinary typed value does not retain its original Ruddy provenance at an unrelated future input site.
- Ordinary native foreign adapters convert using the same instantiated representation before and after the call. The generated adapter, not the raw JS function, receives evidence. Retain evidence and conversion state across asynchronous completion and through supported callbacks.
- Array conversion uses native JS arrays externally and persistent Ruddy arrays internally, recursively converting elements. Conversion cannot share mutable native array storage with the persistent array. The original Ruddy array is unaffected by JS mutation; a reconstructed Ruddy array is unaffected by later mutation through a retained JS alias. No general deep cloning of opaque host objects or identity-bearing payloads is implied.
- Structural conversion must account for nested records, sums, arrays, and supported callable positions, rather than recognizing only top-level arrays. Preserve established primitive numeric and callable contracts. Specify and test the native encoding of every supported structural constructor as part of the implementation; do not expose private persistent-array storage as the default ABI. Types without a sound supported native conversion fail explicitly instead of gaining arbitrary instances or pass-through fallbacks.
- Checked `ForeignValue` decoding returns a standard `Result` with structured mismatch information identifying the failing nested position and expected shape. Unsupported decoding is an error. Host functions can be retained as `ForeignValue`; inspecting that a host value is callable does not prove an arbitrary Ruddy function type or its effects. Do not claim that arbitrary function contracts can be dynamically verified.
- Typed extern and concrete host adapter conversions uphold their declared contracts. Malformed data or unsupported conversion at those trusted interfaces is a foreign contract failure, consistent with existing foreign runtime failure handling; it does not silently invent a successful value or add a new domain effect. Explicit decoding is the recoverable interface for potentially invalid input.
- JS property access and other host observations during conversion can execute host behavior or throw. Preserve established foreign completion and failure handling; cyclic or unsupported host structures must not cause the compiler to loop, and runtime decoding must terminate with a supported result or a defined error rather than blindly traversing cycles forever.
- Callback conversion retains the existing effect coverage, currying, completion protocol, and handler evidence rules. A descriptor is not an effect handler. Unknown types and unsupported callback contracts must not bypass existing checks. No new ability to infer or verify arbitrary JS callback effects is introduced.
- Preserve compiler-recognized runtime intrinsics and their internal representation contracts, including persistent-array operations. Migrate standard-library and generated platform adapters affected by the new default native conversion. Distinguish internal calls through trusted compiler recognition or existing metadata syntax, not a new source grammar or arbitrary JavaScript-string inference.
- Region and presence ownership remain enforced. Packaging a cell, an aggregate containing cells, or a closure capturing state cannot erase dependencies used by escape checking. Preserve those dependencies in accepted semantics or conservatively reject the unsafe boxing or conversion; no existential region escape or implicit promotion is introduced.
- Portable library artifacts retain unresolved generic requirements and original callable interfaces. Root JS host adaptation checks requirements introduced both by Ruddy invocation and by host conversion. A body being erased does not automatically make its native host interface representable.
- Every JS-visible invocation must obtain its required evidence from concrete exported types or evidence captured by an already adapted callable. Check nested and recursive callable positions, not only the outermost export. Reject unresolved requirements in both project checking and building with the public name, offending callable position, and unresolved type information.
- Do not reject a dependency or private helper solely because its portable interface retains requirements; enforce the actual host root contract. Top-level initialization must have all evidence needed by operations it executes. There is no ambient bundle-wide default descriptor. An uncalled generic definition may publish a requirement in its portable interface.
- Concrete wrappers and ordinary annotations can fix generic parameters, including to `ForeignValue` when permitted by the structural signature. Such a dynamic wrapper always uses the `ForeignValue` descriptor and never guesses a more specific Ruddy type from its argument. JS callers cannot supply public descriptor arguments in this version.
- Lower semantic representation needs before existing representation erasure. Add explicit descriptor/package/conversion operations or equivalently reviewed lowered plans. Keep the language-level boxed `Any` distinct from the existing lowered representation meaning that the compiler has not pinned down a value's layout.
- Extend evidence argument construction, captures, curry adapters, CPS calls, and conversion planning for representation evidence. The JS backend implements graph descriptors and structural conversion; the portable artifact carries sufficient target-neutral identities and reviewed operations for separate compilation.
- Artifact schema and compiler cache stamps must change as needed for requirements, descriptor graphs, and callable conventions. Validate bound references, graph references, package operations, and evidence layouts before imported artifacts become trusted. Descriptor equality across linked bundles must be structural, not dependent on descriptor allocation addresses.
- Include inferred requirements in the semantic interface information that drives dependency invalidation. An unchanged written signature can accompany a changed evidence convention when an implementation begins inspecting its type. Do not reuse stale callers after such changes.
- Source printers retain existing syntax. Hover, diagnostics, and debugger views may explain which types need runtime information separately in prose or structured metadata. Do not print an unparseable `requires` clause as if it were a source annotation.

## Testing Decisions

- Prefer the existing source-to-bundle compilation seam and generated-JavaScript execution seam. Assert observable acceptance, diagnostics, imported behavior, conversion results, and host-visible values. Add lower-level tests only for invariants that cannot be established at those interfaces, such as rejecting malformed public artifact data. No new public testing interface is required.
- Use the core compiler's accepted and partial compilation results for inference and rejection tests. Prior art includes polymorphic extern boundary diagnostics, callback effect coverage, array inference, annotated polymorphic recursion, presence ownership, and region escape tests.
- Use the existing project check/build and Node execution harnesses for foreign conversion, opaque transport, and host exports. Prior art includes runtime bundle assertions, persistent-array execution, mutation across callbacks and suspension, and root host adaptation of curried and recursive callable interfaces.
- Exercise boxing and downcasting for distinct primitives, fixed-width numbers sharing JS representations, arrays including empty arrays, nested records and sums, unit, aliases, and admissible recursive types. Verify mismatches and exact equality, including equivalent aliases produced by different bundles.
- Exercise generic and explicitly annotated boxing, generic native extern identity, independent parameters, compound types, forwarding chains, higher-order invocation, function values in aggregates, control-flow joins, currying, returned closures, and recursive groups. Observe both evidence-demanding and erased behavior through the public semantic interface and execution rather than snapshotting private parameter indices.
- Test substitution that makes two demands identical, and higher-order positions that combine erased and reified implementations. Verify evidence layout adaptation through actual calls, including separate compilation.
- Test descriptor construction for row-polymorphic inputs and settled presences, plus rejection where abstract or hidden information is unavailable. Ensure existing presence-package ownership and region safety tests continue to hold.
- For native arrays, make the foreign implementation assert that its argument is a native JS array. Verify recursive conversion, empty arrays, mismatched elements, round trips at multiple generic instantiations, and persistent operations on the returned value.
- Verify both directions of array ownership: foreign mutation cannot alter the original Ruddy array, and mutation of a retained host alias cannot alter an imported Ruddy snapshot. Preserve deliberate identity for opaque host values and established identity-bearing runtime contracts.
- Exercise immediate and Promise foreign completion and supported callbacks. Verify that evidence survives suspension, that callback handlers remain correct, and that unsupported effect or protocol contracts remain rejected.
- Retain an `Any` in JS and return it through a later call with no statically known payload type. Downcast successfully to its original type. Reject forged packages. Contrast native conversion followed by unrelated `ForeignValue` input, which must require decoding rather than recovering fabricated provenance.
- Cover arbitrary `ForeignValue` retention and forwarding, including null, undefined, native functions, symbols, big integers, objects, and cyclic host objects. Verify successful supported decoding, nested mismatch errors, and explicit unsupported or cyclic decoding failures.
- Use host-export tests to distinguish portable generic interfaces from unresolved JS root exports. Include concrete numeric and array wrappers, deliberate `ForeignValue` wrappers, captured evidence, returned functions, curried arrows, records, arrays, sums, and recursive interfaces. Verify both check and build errors.
- Add artifact round trips and producer/consumer compilation tests for descriptor graphs, requirements, adaptation, structural equality, and imported aliases. Follow existing array and CPS artifact validation tests for malformed metadata. Exercise interface invalidation when only inferred evidence needs change.
- Add bounded-stack and bounded-resource stress cases for recursive type descriptors and demand propagation, including representative higher-order and recursive generic cases admitted by the language. Test failures causally rather than accepting a timeout as normal compiler behavior.
- Keep formatter and source/type printer regression coverage: no new grammar or source constraint spelling is expected. Add focused hover and diagnostic assertions for understandable representation requirements and export failures.
- Run the complete Rust test process only through `just test`. Never invoke `cargo test` directly, including for focused tests. During implementation run the repository's appropriate required checks through their supported recipes.
- The user approved these existing seams: source-to-bundle compilation and generated JavaScript execution, with artifact/import tests for separate compilation and diagnostics/export tests for rejected programs. No new public testing seam is planned.

## Out of Scope

- Traits, type classes, instance declarations, overlapping implementation resolution, associated types, and user-written constraint solving.
- A `requires` keyword or any other new source grammar for representation requirements, explicit type arguments, descriptor construction, or descriptor matching.
- Public general-purpose `TypeRep` values, user-defined typed structural inspection, type-level computation, and general existential introduction or elimination.
- Nominal user-defined type identity or descriptor identity based on declaration names, compiler-local symbols, or allocation addresses.
- Tagging every ordinary value with its Ruddy type, passing descriptors to every polymorphic function, and requiring monomorphization to implement generic boxing or native conversion.
- Numeric conversion, structural subtyping, coercion, or JS shape testing as a successful exact `Any` downcast.
- Reconstructing original Ruddy provenance from unannotated native JS values or retaining it automatically through native conversion, cloning, JSON serialization, or unrelated host input.
- A JS-visible descriptor-construction interface or export mode that accepts explicit type witnesses from JS callers. Concrete exports and deliberate `ForeignValue` instantiations suffice for this version.
- Proving arbitrary JavaScript implementations parametric, pure, or compatible with an arbitrary Ruddy function contract by inspecting their runtime values.
- A universal serializer for every host object, automatic custom encodings selected by type name, or new public encodings for unsupported resources without a defined conversion contract.
- General deep cloning of opaque objects, preservation of all native object-graph aliases during structural decoding, or a new zero-copy ownership model for mutable JS arrays.
- New region packaging, promotion, threading, or mutation effects, and changes to the established foreign completion and handler semantics.
- New backend implementations. Preserve portable artifact semantics while implementing this feature for the existing JavaScript backend.

## Further Notes

The final design supersedes the earlier suggestions of explicit `Typeable` and `JsAbi` predicates and a source-level `requires` clause. There is one compiler-owned structural representation mechanism with completely inferred evidence needs. The distinction between runtime representation requirements and computational effects remains internal and semantically important.

"Only Any contains runtime type information" means ordinary payloads do not gain descriptors. Hidden representation arguments, shared descriptor graphs, and captured evidence are explicitly allowed as the cost of shared generic implementations. Existing sum tags are not full Ruddy type reflection.

`Any` has existential semantics internally, but general existential types are not a prerequisite for the source language. Its compiler-supported operations establish the required descriptor/payload relationship. Existing presence packages retain their separate ownership rules.

The discussion fixed the contracts and architecture, not a public JS object schema for every structural constructor. The implementation should document its native encoding decisions and test them without introducing nominal customization or new source syntax. Conservative rejection remains required where the current type/region information cannot justify a representation or supported conversion.

The work is isolated on branch `inferred-type-representations` in a dedicated sibling worktree, created from the current `main` commit `7656326`. This spec is the local issue-tracker entry for the subsequent implementation. No compiler implementation is part of creating this spec.
